# SyntheticBondTradeUi и ttSpreadBot: подробная справка по настройкам

Документ описывает текущее окно `SyntheticBondTradeUi` и нашего бота `ttSpreadBot` простыми словами, но с привязкой к коду. Цель: по этой справке можно отвечать на вопросы по настройкам без догадок.

Проверенные файлы:

- `D:\AlgoTrading\OsEngine\project\OsEngine\OsTrader\Panels\Tab\SyntheticBondTab\SyntheticBondTradeUi.xaml.cs`
- `D:\AlgoTrading\OsEngine\project\OsEngine\OsTrader\Panels\Tab\SyntheticBondTab\BondScenario.cs`
- `D:\AlgoTrading\OsEngine\project\OsEngine\Robots\temkamm\tt.SpreadBot.cs`
- `D:\AlgoTrading\OsEngine\project\OsEngine\OsTrader\Iceberg\ArbitrationIceberg.cs`
- `D:\AlgoTrading\OsEngine\project\OsEngine\OsTrader\Iceberg\Entity\ArbitrationLeg.cs`
- `D:\AlgoTrading\OsEngine\project\OsEngine\OsTrader\Panels\Tab\BotTabSimple.cs`

## 1. Что это окно делает

`SyntheticBondTradeUi` - окно настройки одной спред-пары.

Спред-пара состоит из двух ног:

- `База` - первая нога, в коде `MainLegs[0]`.
- `Фьючерс` - вторая нога, в коде `SecondaryLegs[0]`.

`ttSpreadBot` не выставляет ордера сам. Он смотрит на текущий исполнимый bid/ask спред и решает, когда дать команду исполнителю.

`ArbitrationIceberg` - исполнитель ордеров. Он получает команду открыть или закрыть и дальше работает по настройкам вкладок `Вход в позицию` и `Выход из позиции`.

Коротко по ролям:

- `ttSpreadBot` - решает когда входить и выходить.
- `BondScenario` - хранит состояние пары, пороги спреда и циклы.
- `SyntheticBondTradeUi` - даёт пользователю менять настройки.
- `ArbitrationIceberg` - выставляет ордера и ведёт шаги набора/закрытия.
- `BotTabSimple` - реально отправляет заявки в OsEngine.

## 2. Главный алгоритм нашего бота

Бот реагирует на потоковые обновления котировок двух ног:

- `MarketDepthUpdateEvent` - обновление стакана, где есть цена и объём лучшего `Bid/Ask`;
- `BestBidAskChangeEvent` - обновление лучшего `Bid/Ask` без объёма.

Основной источник - стакан. Если на лучшем `Bid` или `Ask` изменилась цена или объём, котировка этой ноги считается обновлённой.

После любого обновления одной ноги бот пересчитывает спред по новой котировке этой ноги и последней известной котировке второй ноги.

Если сценарий `Stopped`, бот ничего по нему не делает.

Если сценарий `Running`, бот может открыть позицию, если выполнено условие входа по bid/ask спреду.

Если сценарий `Running` или `PauseOnlyClose` и позиция уже есть, бот может закрыть позицию, если выполнено условие выхода по bid/ask спреду.

Если сценарий `PauseOnlyClose`, новые входы запрещены. Разрешён только штатный выход по спреду.

Если сценарий `StoppingNow`, новые входы запрещены. Бот ждёт, пока позиции реально исчезнут.

Если после `PauseOnlyClose` или `StoppingNow` позиций больше нет, состояние переводится в `Stopped`.

После полного штатного закрытия цикла бот увеличивает `CompletedCycles`.

Если `CompletedCycles >= CyclesCount`, сценарий переводится в `Stopped`.

Перед запуском входа или выхода бот делает повторную проверку спреда. Если сигнал был, но прямо перед отправкой ордеров спред ушёл, `ArbitrationIceberg` не запускается и в лог пишется отмена.

## 3. Состояния пары

`Stopped` - пара остановлена. Новых входов нет, штатного выхода нет. Кнопка `Старт` активна.

`Running` - пара запущена. Бот ждёт вход или, если позиция уже есть, ждёт выход.

`PauseOnlyClose` - пауза только на закрытие. Новые входы запрещены. Если позиция есть, бот ждёт обычный выход по спреду.

`StoppingNow` - аварийная остановка. UI отправил закрытие всех живых позиций по рынку. Пока позиция есть, сценарий не считается остановленным.

При перезапуске программы:

- `PauseOnlyClose` без позиции восстанавливается как `Stopped`.
- `StoppingNow` с позицией восстанавливается как `PauseOnlyClose`.
- `StoppingNow` без позиции восстанавливается как `Stopped`.

## 4. Верхняя часть окна

### Текущий режим

Это направление сделки.

`Купить базу, продать фьючерс`:

- база покупается;
- фьючерс продаётся;
- вход: когда `EntrySpread >= Макс спред`;
- выход: когда `ExitSpread <= Мин спред`.

Формула входа:

`EntrySpread% = (FuturesBid - BaseAsk) / BaseAsk * 100`

Формула выхода:

`ExitSpread% = (FuturesAsk - BaseBid) / BaseBid * 100`

Пример:

- `Макс спред = 0.20`
- `Мин спред = 0.15`
- режим `Купить базу, продать фьючерс`
- если `EntrySpread` стал `0.21`, бот запускает вход;
- если после входа `ExitSpread` стал `0.14`, бот запускает выход.

`Продать базу, купить фьючерс`:

- база продаётся;
- фьючерс покупается;
- вход: когда `EntrySpread >= Макс спред`;
- выход: когда `ExitSpread <= Мин спред`.

Формула входа:

`EntrySpread% = (BaseBid - FuturesAsk) / FuturesAsk * 100`

Формула выхода:

`ExitSpread% = (BaseAsk - FuturesBid) / FuturesBid * 100`

Пример:

- `Макс спред = 0.20`
- `Мин спред = 0.15`
- режим `Продать базу, купить фьючерс`
- если `EntrySpread` стал `0.21`, бот запускает вход;
- если после входа `ExitSpread` стал `0.14`, бот запускает выход.

Другие внутренние режимы `ArbitrationIceberg` для запуска нашего `ttSpreadBot` не нужны. Наш `Старт` разрешает только два режима входа.

### Текущий спред (%)

Это текущий bid/ask spread в процентах по выбранному режиму.

Если выбран режим `Купить базу, продать фьючерс`, формула такая:

`DisplaySpread% = (FuturesBid - BaseAsk) / BaseAsk * 100`

Если выбран режим `Продать базу, купить фьючерс`, формула такая:

`DisplaySpread% = (BaseBid - FuturesAsk) / FuturesAsk * 100`

То есть поле показывает именно тот исполнимый спред, по которому бот будет искать вход в текущем выбранном направлении.

Поле обновляется не на каждом тике, а примерно раз в 1 секунду, чтобы цифры не мелькали слишком быстро.

Торговая логика при этом работает быстрее: она пересчитывает спред на каждом обновлении котировки.

Если `ttSpreadBot` ещё не получил полный bid/ask снимок обеих ног, окно может временно показать старое значение из `SyntheticBond.PercentSeparationCandles`. Это только запасной fallback для отображения, не основной источник торгового сигнала.

### Макс спред (%)

Верхний порог спреда.

В обоих режимах это порог входа:

- вход разрешён при `EntrySpread >= Макс спред`;
- перед запуском ордеров повторная проверка требует `EntrySpread >= Макс спред + 0.01%`.

Поле обязательно должно быть больше `Мин спред`.

Если `Макс спред <= Мин спред`, оба поля краснеют и `Старт` блокируется.

### Мин спред (%)

Нижний порог спреда.

В обоих режимах это порог выхода:

- выход разрешён при `ExitSpread <= Мин спред`;
- перед запуском закрытия повторная проверка требует `ExitSpread <= Мин спред - 0.01%`.

Поле обязательно должно быть меньше `Макс спред`.

### Циклов нужно

Сколько полных циклов `вход -> выход` должна сделать пара.

`0` сейчас считается ошибкой. При `0` поле краснеет и `Старт` блокируется.

Пример:

- `Циклов нужно = 1`;
- бот открыл позицию;
- бот закрыл позицию;
- `Циклов сделано` стало `1`;
- бот переводит сценарий в `Stopped`.

Если `Циклов нужно = 3`, бот должен сделать 3 полных закрытых цикла.

### Циклов сделано

Сколько циклов уже закрыто.

Поле информационное, редактировать его через окно нельзя.

Бот увеличивает это поле только после полного закрытия позиции, которую он считал штатным циклом.

### Старт

Кнопка не открывает позицию сразу.

Она только переводит сценарий в `Running`.

После этого бот ждёт следующее обновление котировки любой ноги и проверяет условия входа.

Перед стартом UI проверяет:

- `Макс спред > Мин спред`;
- `Циклов нужно > 0`;
- выбран режим входа, а не внутренний режим закрытия;
- обе ноги готовы к торговле;
- лимит циклов ещё не достигнут.

После старта поля настройки блокируются, чтобы не менять параметры во время работы.

### Пауза

Переводит сценарий в `PauseOnlyClose`.

Новые входы запрещены.

Если позиция уже открыта, бот продолжит ждать штатное условие выхода по спреду.

Если позиции нет, состояние будет переведено в `Stopped`.

### Стоп

Кнопка `Удалить` в нашей версии используется как `Стоп`.

Сценарий не удаляется.

Если открытых позиций нет, состояние становится `Stopped`.

Если открытые позиции есть, UI вызывает по каждой живой позиции:

`BotTab.CloseAtMarket(position, position.OpenVolume)`

После этого сценарий получает состояние `StoppingNow`.

Важно: аварийный `Стоп` не использует вкладку `Выход из позиции`. Он закрывает фактический открытый объём по рынку.

Сценарий не считается остановленным, пока есть живая позиция.

### Неторговый период

Это настройка времени, когда `ArbitrationIceberg` не должен выставлять ордера.

Внутри основного потока `ArbitrationIceberg` проверяет `NonTradePeriods.CanTradeThisTime(_currentTimeServer)`.

Если сейчас неторговый период, исполнитель спит и не делает торговую логику.

Важно: `ttSpreadBot` может увидеть точку входа и запустить `ArbitrationIceberg`, но сам исполнитель не будет выставлять ордера, пока время запрещено.

### Временной сдвиг (час)

Сдвиг времени для `_currentTimeServer`.

Исполнитель считает текущее время так:

`DateTime.UtcNow.AddHours(TimeShift)`

Это влияет на проверку неторговых периодов и часть логики времени внутри исполнителя.

### Текущее время сервера

Информационное поле.

Показывает время, которое видит `ArbitrationIceberg`.

Если данных нет, показывает `None`.

### Макс возраст котировки (сек)

Поле находится во вкладке `Инфо` окна `SyntheticBondTradeUi`.

Значения:

- `10` по умолчанию;
- `0` отключает проверку возраста;
- любое положительное число задаёт максимум секунд с последнего обновления котировки ноги.

Котировка ноги обновляется, если на лучшем уровне изменились цена или объём `Bid` или `Ask`.

Если одна из ног старше лимита, бот не открывает и не закрывает позицию по этой паре. В лог пишется причина без спама. Когда котировки снова стали нормальными, бот пишет восстановление условий.

Значение применяется сразу после изменения поля и сохраняется в сценарии пары.

### Вкладка Инфо

Вкладка `Инфо` находится после вкладки `Позиции закрытые`.

В ней показываются:

- `Макс возраст котировки (сек)` - настройка контроля свежести котировок;
- строка фьючерса - название инструмента, собственный биржевой спред `Ask - Bid` в пунктах и процентах, текущие `Ask` и `Bid`;
- строка базы - название инструмента, собственный биржевой спред `Ask - Bid` в пунктах и процентах, текущие `Ask` и `Bid`.

База находится ниже второй ноги. Используемые для текущего режима цены подсвечиваются:

- `Купить базу, продать фьючерс`: `Ask` базы синим, `Bid` фьючерса красным;
- `Продать базу, купить фьючерс`: `Bid` базы красным, `Ask` фьючерса синим.

Процент собственного спреда инструмента считается так:

`(Ask - Bid) / Bid * 100`

## 5. Вкладка Вход в позицию

Эта вкладка задаёт, как открывать позицию по каждой ноге.

Левая часть - `База`, то есть `MainLegs[0]`.

Правая часть - `Фьючерс`, то есть `SecondaryLegs[0]`.

Настройки задаются отдельно для каждой ноги.

### Asset in portfolio

Используется только при `Тип объёма = Процент депозита`.

`Prime` значит считать процент от общей текущей стоимости портфеля `Portfolio.ValueCurrent`.

Если указать конкретный актив, код ищет его в `Portfolio.GetPositionOnBoard()` по `SecurityNameCode` и берёт `ValueCurrent` этой позиции.

Если актив не найден или его стоимость `0`, объём считается `0`, а в лог пишется:

`Can't found portfolio ...`

При `Тип объёма = Контракты` поле не влияет.

При `Тип объёма = Валюта контракта` поле не влияет.

### Тип объёма: Контракты

Числа в `Объем общий` и `Один ордер` считаются как контракты или лоты.

Формула в коде простая:

`итоговый объём = введённое значение`

Пример:

- `Объем общий = 10`;
- `Один ордер = 3`;
- исполнитель создаст шаги `3 + 3 + 3 + 1`.

### Тип объёма: Валюта контракта

Числа в `Объем общий` и `Один ордер` считаются как деньги в валюте инструмента.

Код берёт `PriceBestAsk` и делит сумму на цену.

Основная формула:

`объём = введённая сумма / PriceBestAsk`

Если для сервера включено правило расчёта через лот и `Lot > 1`, формула такая:

`объём = введённая сумма / (PriceBestAsk * Lot)`

Потом объём округляется до `Security.DecimalsVolume`.

Пример без лота:

- `Объем общий = 1000`;
- `PriceBestAsk = 100`;
- итоговый объём будет примерно `10`.

Пример с лотом:

- `Объем общий = 1000`;
- `PriceBestAsk = 100`;
- `Lot = 10`;
- итоговый объём будет примерно `1`.

Важно: для этого типа код использует `PriceBestAsk`, даже если нога будет продаваться.

### Тип объёма: Процент депозита

Число в `Объем общий` или `Один ордер` считается как процент.

Сначала код определяет базовую стоимость:

- если `Asset in portfolio = Prime`, берёт `Portfolio.ValueCurrent`;
- иначе ищет конкретный актив в портфеле и берёт его `ValueCurrent`.

Потом считает деньги на позицию:

`moneyOnPosition = portfolioPrimeAsset * (incomingVolume / 100)`

Основная формула количества:

`qty = moneyOnPosition / PriceBestAsk / Lot`

Если у инструмента включён расчёт через `PriceStepCost`, используется отдельная формула:

`qty = moneyOnPosition / (PriceBestAsk / PriceStep * PriceStepCost)`

Потом объём округляется до `Security.DecimalsVolume`.

Пример:

- портфель `100000`;
- `Объем общий = 10`;
- значит на позицию берётся примерно `10%`, то есть `10000`;
- если `PriceBestAsk = 100`, а `Lot = 1`, объём будет примерно `100`.

Важно: этот режим зависит от корректной стоимости портфеля и цены Ask. Если портфель или Ask не пришли, объём может стать `0`.

### Объем общий

Это общий объём, который нужно набрать по этой ноге при входе.

При `Тип объёма = Контракты` это прямо количество контрактов/лотов.

При `Тип объёма = Валюта контракта` это сумма денег, которая будет переведена в объём через Ask.

При `Тип объёма = Процент депозита` это процент от выбранной портфельной стоимости.

Если значение `0` или меньше, поле краснеет и `Старт` блокируется.

### Один ордер

Это размер одного шага набора позиции.

Значение должно быть больше `0` и не больше `Объем общий`.

Если `Один ордер` больше `Объем общий`, поле краснеет и `Старт` блокируется.

Пример для `Контракты`:

- `Объем общий = 10`;
- `Один ордер = 3`;
- шаги будут `3 + 3 + 3 + 1`;
- последний шаг меньше, потому что остаток только `1`.

Пример:

- `Объем общий = 10`;
- `Один ордер = 10`;
- будет один шаг `10`.

Техническая логика шагов:

- при старте входа `ArbitrationIceberg` создаёт список `EnterArbitrationSteps`;
- каждый шаг имеет `VolumeStep`;
- шаг считается выполненным, когда фактически набранный объём позиции дошёл до объёма шага;
- если шаг выполнен, исполнитель переходит к следующему шагу.

### Тип ордера: Market

При выполнении шага отправляется рыночная заявка.

Для первой заявки позиции используются:

- `BuyAtMarket`, если нога должна покупаться;
- `SellAtMarket`, если нога должна продаваться.

Для добора уже существующей позиции используются:

- `BuyAtMarketToPosition`;
- `SellAtMarketToPosition`.

`Положение`, `Ask/Bid/Middle`, `Проскальзывание` и `Время жизни ордера` для Market-входа не применяются.

Важно: внутри `BotTabSimple` если биржа не поддерживает настоящие market-ордера, OsEngine может отправить агрессивную лимитную заявку. Для пользователя в этом окне это всё равно режим `Market`.

### Тип ордера: Limit

При выполнении шага отправляется лимитная заявка.

Объём берётся из текущего шага.

Цена считается так:

1. Берётся базовая цена по полю `Положение`.
2. К базовой цене прибавляется или вычитается `Проскальзывание`.
3. По этой цене отправляется лимитная заявка.

Для первой заявки используются:

- `BuyAtLimit`;
- `SellAtLimit`.

Для добора уже существующей позиции используются:

- `BuyAtLimitToPosition`;
- `SellAtLimitToPosition`.

Шаг считается выполненным не по факту выставления заявки, а по фактически набранному объёму позиции.

### Положение: Ask

Для Limit-входа базовая цена берётся от лучшего Ask.

Ask - лучшая цена продавца в стакане.

Если покупаем, `Ask` обычно ближе к немедленному исполнению.

Если продаём, `Ask` обычно стоит выше рынка и может не исполниться сразу.

### Положение: Bid

Для Limit-входа базовая цена берётся от лучшего Bid.

Bid - лучшая цена покупателя в стакане.

Если покупаем, `Bid` обычно даёт более пассивную покупку.

Если продаём, `Bid` обычно ближе к немедленному исполнению.

### Положение: Middle

Базовая цена считается как середина:

`(Ask + Bid) / 2`

Если Ask или Bid равны `0`, цена не считается и ордер не отправляется.

### Проскальзывание для входа

Для входного Limit это не проверка фактического проскальзывания.

Это просто поправка к цене лимитной заявки.

Если нога покупается:

`цена = базовая цена + проскальзывание`

Если нога продаётся:

`цена = базовая цена - проскальзывание`

Пример покупки:

- `Положение = Ask`;
- `Ask = 100`;
- `Проскальзывание = 2`;
- лимитная цена будет `102`.

Пример продажи:

- `Положение = Bid`;
- `Bid = 100`;
- `Проскальзывание = 2`;
- лимитная цена будет `98`.

Если `Тип ордера = Market`, это поле не применяется.

### Время жизни ордера (сек) для входа

Поле сохраняется и валидируется для Limit-режима.

Но в текущем коде входа `ArbitrationIceberg` оно фактически не используется.

То есть входная лимитная заявка по этому полю не отменяется.

Это важный риск перед боевой торговлей.

Если `Тип ордера = Market`, поле не применяется.

### Частота ордеров (сек) для входа

Это минимальная пауза между попытками отправить ордер по этой ноге.

Применяется и для `Market`, и для `Limit`.

Если стоит `5`, следующая отправка по этой ноге возможна не раньше чем через 5 секунд после прошлой попытки.

Пример:

- есть точка входа;
- `Объем общий = 10`;
- `Один ордер = 3`;
- `Частота ордеров = 5`;
- исполнитель будет добирать шагами не чаще одного раза в 5 секунд по этой ноге.

Важно для Limit-входа:

- код входа не ждёт отмены старой входной лимитки по `Время жизни ордера`;
- следующая попытка может быть отправлена через `Частота ордеров`;
- поэтому перед боевой торговлей Limit-вход нужно отдельно тестировать.

Если частота `0` или меньше, поле краснеет и `Старт` блокируется.

### Объем взят

Информационное поле.

Показывает фактически открытый объём по ноге, который видит исполнитель.

## 6. Порядок открытия ног

Исполнитель не отправляет обе ноги одновременно.

По текущему коду входа:

1. Сначала выполняется текущий шаг первой ноги (`База`).
2. Когда шаг первой ноги выполнен, выполняется текущий шаг второй ноги (`Фьючерс`).
3. Потом выбираются следующие невыполненные шаги.
4. Процесс повторяется.

Пример:

- база: `Объем общий = 10`, `Один ордер = 3`;
- фьючерс: `Объем общий = 10`, `Один ордер = 3`.

Примерная последовательность:

- база `3`;
- фьючерс `3`;
- база `3`;
- фьючерс `3`;
- база `3`;
- фьючерс `3`;
- база `1`;
- фьючерс `1`.

Это важно: между ногами может быть временной разрыв. Особенно если первая нога Limit и долго не исполняется.

## 7. Вкладка Выход из позиции

Эта вкладка задаёт штатный выход по условию спреда.

Аварийный `Стоп` эти настройки не использует.

### Asset in portfolio

На выходе отдельно не редактируется.

Синхронизируется с вкладкой входа.

Для штатного выхода фактический общий объём берётся из открытой позиции, а не из портфеля.

### Тип объёма

На выходе отдельно не редактируется.

Синхронизируется с вкладкой входа.

Для `Один ордер` на выходе тип объёма всё равно используется при расчёте размера шага закрытия.

### Объем общий

На выходе поле информационное.

При закрытии общий объём берётся из текущей открытой позиции:

`leg.ArbitrationLegStatistic.CurrentPosition.OpenVolume`

То есть если фактически открыто `7`, закрывать будет `7`, даже если раньше в настройках входа было `10`.

### Один ордер

Размер одного шага закрытия.

Пример:

- открытая позиция `10`;
- `Один ордер = 3`;
- штатное закрытие создаёт шаги `3 + 3 + 3 + 1`.

Если `Один ордер` больше `Объем общий`, поле краснеет.

### Тип ордера: Market

Штатное закрытие идёт через:

`CloseAtMarket(position, closeVolume)`

`Положение`, `Проскальзывание` и `Время жизни ордера` для Market-закрытия не применяются.

Если биржа не поддерживает настоящие market-ордера, OsEngine может закрывать агрессивной лимитной заявкой. Для пользователя это всё равно режим `Market`.

### Тип ордера: Limit

Штатное закрытие идёт через:

`CloseAtLimit(position, price, closeVolume)`

Цена считается из `Положение` и `Проскальзывание`.

### Положение для выхода

Выбирает базовую цену лимитки:

- `Ask` - лучший Ask;
- `Bid` - лучший Bid;
- `Middle` - `(Ask + Bid) / 2`.

Если Ask или Bid равны `0`, цена не считается и ордер не отправляется.

### Проскальзывание для выхода

Работает наоборот относительно входа, потому что позиция закрывается встречной сделкой.

Если закрывается длинная позиция `Buy`, то закрытие идёт продажей:

`цена = базовая цена - проскальзывание`

Если закрывается короткая позиция `Sell`, то закрытие идёт покупкой:

`цена = базовая цена + проскальзывание`

Пример закрытия длинной позиции:

- позиция была `Buy`;
- `Положение = Bid`;
- `Bid = 100`;
- `Проскальзывание = 2`;
- лимитная цена закрытия будет `98`.

Пример закрытия короткой позиции:

- позиция была `Sell`;
- `Положение = Ask`;
- `Ask = 100`;
- `Проскальзывание = 2`;
- лимитная цена закрытия будет `102`.

### Время жизни ордера (сек) для выхода

Для Limit-закрытия реально используется.

Если есть активная заявка закрытия:

- для Market код просто ждёт;
- для Limit код проверяет время жизни;
- если заявка уже отправлена на биржу и висит дольше `Время жизни ордера`, исполнитель отправляет отмену.

Пока активная заявка закрытия висит, новая заявка закрытия не отправляется.

После отмены следующая попытка будет выставлена по новой расчётной цене, но не чаще чем разрешает `Частота ордеров`.

Для Market поле не применяется.

### Частота ордеров (сек) для выхода

Минимальная пауза между попытками закрытия по этой ноге.

Если стоит `5`, новая попытка закрытия по этой ноге не отправится раньше чем через 5 секунд после прошлой.

Для Limit-закрытия есть дополнительное правило: пока активная заявка закрытия висит, новая не отправляется.

Если частота `0` или меньше, поле краснеет и `Старт` блокируется.

### Объем взят

Информационное поле.

Показывает текущий открытый объём позиции по ноге.

## 8. Порядок закрытия ног

Штатный выход тоже идёт шагами.

По текущему коду:

1. Сначала закрывается текущий шаг первой ноги (`База`).
2. Потом закрывается текущий шаг второй ноги (`Фьючерс`).
3. Потом выбираются следующие невыполненные шаги.
4. Процесс повторяется.

Аварийный `Стоп` работает иначе: он проходит все открытые позиции всех ног и отправляет `CloseAtMarket` на весь фактический открытый объём.

## 9. Вкладки Позиции открытые и Позиции закрытые

Эти вкладки показывают шаги работы `ArbitrationIceberg`.

`Шаг` - номер шага.

`Время шага` - когда шаг был активирован.

`Статус` - состояние шага.

`Открытый объем` - сколько объёма уже выполнено в этом шаге.

`Нужный объем` - сколько объёма нужно выполнить в этом шаге.

`Позиция` - кнопка открытия карточки позиции.

Эти вкладки полезны, чтобы понять, на каком шаге застрял вход или выход.

## 10. Что блокируется во время работы

Когда сценарий не `Stopped` или когда `ArbitrationIceberg.CurrentStatus = On`, настройки блокируются.

Блокируются:

- `Текущий режим`;
- `Макс спред`;
- `Мин спред`;
- `Временной сдвиг`;
- `Неторговый период`;
- поля вкладки `Вход в позицию`;
- поля вкладки `Выход из позиции`.

Смысл: нельзя менять параметры, пока пара работает или закрывается.

## 11. Валидация перед стартом

Старт блокируется, если есть красные поля.

Проверки:

- `Макс спред` и `Мин спред` должны быть числами.
- `Макс спред > Мин спред`.
- `Циклов нужно` должно быть целым числом больше `0`.
- `Объем общий` по каждой ноге должен быть больше `0`.
- `Один ордер` должен быть больше `0`.
- `Один ордер` должен быть не больше `Объем общий`.
- `Частота ордеров` должна быть больше `0`.
- Для `Тип ордера = Limit` поле `Время жизни ордера` должно быть больше `0`.

Важно: UI валидирует `Время жизни ордера` для входного Limit, хотя сам входной код это поле сейчас не использует для отмены заявки.

## 12. Как сохраняются настройки

Большинство изменений в полях сразу записываются в модель и вызывают:

`_syntheticBondSeries.OnSettingsChanged()`

Этот метод очищает кеши, сохраняет настройки и вызывает событие изменения настроек.

`Макс спред`, `Мин спред` и `Циклов нужно` дополнительно применяются при клике по свободному месту окна и перед стартом.

Состояние сценария и циклы сохраняются в файле сценария через `BondScenario.Save()`.

Старые файлы без новых строк состояния и циклов загружаются совместимо: состояние остаётся `Stopped`, циклы по умолчанию `0`.

## 13. Типовые примеры настройки

### Пример 1: один цикл, купить базу и продать фьючерс

Настройки:

- режим: `Купить базу, продать фьючерс`;
- `Макс спред = 0.20`;
- `Мин спред = 0.15`;
- `Циклов нужно = 1`;
- `Тип объёма = Контракты`;
- база: `Объем общий = 10`, `Один ордер = 3`;
- фьючерс: `Объем общий = 10`, `Один ордер = 3`.

Что будет:

- нажимаем `Старт`;
- состояние становится `Running`;
- если `EntrySpread = (FuturesBid - BaseAsk) / BaseAsk * 100` стал `0.20` или выше, бот видит сигнал;
- перед ордерами бот проверяет ещё раз, что `EntrySpread >= 0.21`;
- исполнитель набирает базу и фьючерс шагами `3 + 3 + 3 + 1`;
- после полного входа бот ждёт выход;
- если `ExitSpread = (FuturesAsk - BaseBid) / BaseBid * 100` стал `0.15` или ниже, бот видит сигнал на выход;
- перед закрытием бот проверяет ещё раз, что `ExitSpread <= 0.14`;
- после полного закрытия `Циклов сделано = 1`;
- так как лимит `1`, сценарий становится `Stopped`.

### Пример 2: один цикл, продать базу и купить фьючерс

Настройки:

- режим: `Продать базу, купить фьючерс`;
- `Макс спред = 0.20`;
- `Мин спред = 0.15`;
- `Циклов нужно = 1`.

Что будет:

- вход, если `EntrySpread = (BaseBid - FuturesAsk) / FuturesAsk * 100` стал `0.20` или выше;
- перед ордерами бот проверяет ещё раз, что `EntrySpread >= 0.21`;
- выход, если `ExitSpread = (BaseAsk - FuturesBid) / FuturesBid * 100` стал `0.15` или ниже;
- перед закрытием бот проверяет ещё раз, что `ExitSpread <= 0.14`.

### Пример 3: Market с частотой 5 секунд

Настройки:

- `Тип ордера = Market`;
- `Объем общий = 10`;
- `Один ордер = 3`;
- `Частота ордеров = 5`.

Что будет:

- при точке входа исполнитель отправляет первый шаг;
- следующий ордер по этой ноге не отправится раньше чем через 5 секунд;
- шаги будут идти до набора общего объёма;
- `Положение`, `Проскальзывание`, `Время жизни ордера` не влияют.

### Пример 4: Limit-покупка от Ask

Настройки:

- нога покупается;
- `Тип ордера = Limit`;
- `Положение = Ask`;
- лучший Ask в стакане `100`;
- `Проскальзывание = 2`.

Цена заявки:

`100 + 2 = 102`

Это агрессивнее, чем просто поставить по `100`, потому что покупка по `102` готова забрать ликвидность до этой цены.

### Пример 5: Limit-продажа от Bid

Настройки:

- нога продаётся;
- `Тип ордера = Limit`;
- `Положение = Bid`;
- лучший Bid в стакане `100`;
- `Проскальзывание = 2`.

Цена заявки:

`100 - 2 = 98`

Это агрессивнее для продажи, потому что продавец готов продать ниже текущего Bid.

## 14. Важные риски текущей реализации

Сигнал считается по лучшим `Bid/Ask`. Если по одной ноге нет полного `Bid` и `Ask`, бот не торгует эту пару.

Если `Макс возраст котировки (сек)` больше `0`, старая котировка одной ноги блокирует вход и выход. Для неликвидных инструментов это может быть нормально, поэтому параметр можно увеличить или поставить `0`.

Даже при повторной проверке перед запуском ордеров проскальзывание возможно. Повторная проверка защищает только от ситуации, когда спред уже ушёл до старта исполнения.

Входные Limit-заявки не отменяются по `Время жизни ордера`. Поле есть, сохраняется и валидируется, но в коде открытия нет проверки `EnterLifetimeOrder`.

При Limit-входе новая попытка может быть отправлена через `Частота ордеров`, даже если старая лимитка ещё не отменена этим модулем. Это нужно отдельно тестировать перед боевой торговлей.

Открытие и штатное закрытие ног идёт не одновременно: сначала шаг первой ноги, потом шаг второй ноги. Между ногами может быть рыночный риск.

`Тип объёма = Валюта контракта` и `Процент депозита` используют `PriceBestAsk` для расчёта объёма. Это важно даже для продающей ноги.

Если Ask или Bid равны `0`, лимитная цена не считается и ордер не отправляется.

Если портфель или актив для `Процент депозита` не найден, объём становится `0`.

`Стоп` по Market закрывает все открытые позиции ног, которые видит `PositionsOpenAll`. Он не ждёт настройки вкладки выхода.

`Циклов сделано` увеличивается после полного закрытия сценария, который бот отслеживал как штатное закрытие. Ручные вмешательства могут нарушить ожидаемый сценарий подсчёта, поэтому ручные действия надо проверять отдельно.

## 15. Что проверять перед боевой торговлей

Минимальный тестовый набор:

- `Market` вход и `Market` выход на малом объёме.
- Проверка, что поле `Текущий спред (%)` обновляется примерно раз в 1 секунду.
- Проверка двух режимов: `Купить базу, продать фьючерс` показывает `FuturesBid - BaseAsk`, а `Продать базу, купить фьючерс` показывает `BaseBid - FuturesAsk`.
- Проверка повторной отмены: сигнал появился, но перед ордерами спред ушёл.
- Проверка `Макс возраст котировки (сек) = 10`.
- Проверка `Макс возраст котировки (сек) = 0`, чтобы контроль возраста отключался.
- Проверка поведения, если по одной ноге нет `Bid` или `Ask`.
- `Limit` вход с `Положение = Ask`, `Bid`, `Middle`.
- `Limit` выход с `Положение = Ask`, `Bid`, `Middle`.
- `Один ордер`, который ровно делит общий объём.
- `Один ордер`, который не делит общий объём, например `10` и `3`.
- `Частота ордеров = 5`, чтобы увидеть паузу между шагами.
- `Пауза` без позиции.
- `Пауза` с открытой позицией.
- `Стоп` с открытой позицией.
- Проверка, что `Циклов сделано` увеличивается после полного закрытия.
- Проверка, что после достижения `Циклов нужно` сценарий становится `Stopped`.

Отдельно обязательно проверить Limit-вход с неисполняющейся заявкой, потому что текущий код не отменяет входную лимитку по `Время жизни ордера`.
