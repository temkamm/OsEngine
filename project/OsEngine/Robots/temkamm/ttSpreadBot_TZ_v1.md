# ТЗ v1: минимальная доработка `SyntheticBondTradeUi` под простой спред-бот

## 1. Цель

Сделать минимальную рабочую доработку текущего модуля `SyntheticBond`, без создания нового большого модуля и без копии `SyntheticBond` / `ArbitrationIceberg`.

Нужный результат:
- каждая пара управляется отдельно через своё окно `SyntheticBondTradeUi`;
- окно пары является основным местом настройки и управления торговлей;
- торговая логика работает по простому спреду `MinSpread / MaxSpread`;
- общий `Regime` у `ttSpreadBot` в v1 не используется и убирается из параметров бота.

## 2. Общий подход

- Не создавать новый отдельный модуль.
- Не копировать `SyntheticBond` и `ArbitrationIceberg`.
- Минимально доработать:
  - `SyntheticBondTradeUi`
  - `BondScenario`
  - связанную логику запуска/остановки пары
  - при необходимости тонко скорректировать `ttSpreadBot`

## 3. Что остаётся базой

- `SyntheticBond` остаётся основным механизмом хранения пары и расчёта спреда.
- `ArbitrationIceberg` остаётся механизмом исполнения ордеров.
- Вкладки:
  - `Вход в позицию`
  - `Выход из позиции`
  используются как и сейчас для настройки исполнения ног.

## 4. Что не делаем

- Не делаем новый отдельный UI.
- Не делаем новый отдельный торговый движок.
- Не делаем отдельный новый бот на каждую пару через новую архитектуру.
- Не делаем общий аварийный рубильник через `Regime` в v1.

## 5. Поведение окна пары

Окно `SyntheticBondTradeUi` является основным местом:
- настройки входа;
- настройки выхода;
- запуска этой конкретной пары;
- паузы этой конкретной пары;
- остановки этой конкретной пары.

## 6. Кнопки управления

Важно:
- в текущей штатной реализации `Старт` сразу запускает `ArbitrationIceberg` в выбранном режиме;
- в v1 смысл кнопки меняется для нашей рабочей версии: `Старт` включает автоторговлю этой пары и ждёт условия спреда;
- немедленный ручной запуск входа через эту кнопку в v1 не поддерживается.

### 6.1. `Старт`

Когда пара находится в состоянии остановки:
- включает торговлю именно этой пары;
- разрешает новые входы;
- если позиции нет, бот ждёт условия входа;
- если позиция уже есть, просто переводит пару в обычный рабочий режим сопровождения;
- после активации:
  - `Старт` становится обычного цвета;
  - активируются `Пауза` и `Стоп`.

### 6.2. `Пауза`

Режим `OnlyClose` для конкретной пары:
- новые входы запрещены;
- если позиция уже есть, она закрывается только по штатному условию выхода;
- если позиции нет, пара просто ждёт без новых входов;
- если уже идёт закрытие, `Пауза` не мешает ему;
- при нажатии:
  - кнопка подсвечивается жёлтым;
- после полного закрытия позиции:
  - режим паузы автоматически снимается;
  - кнопка возвращается в обычный цвет;
  - состояние пары становится `Stopped`.

### 6.3. `Стоп`

Аварийная остановка конкретной пары:
- имеет приоритет над `Пауза`;
- немедленно запрещает новые входы;
- если есть открытая позиция, запускает немедленное закрытие по `Market`;
- повторные нажатия `Стоп` во время уже идущего аварийного закрытия игнорируются;
- после завершения:
  - состояние пары становится `Stopped`;
  - красная подсветка кнопки снимается.

### 6.4. `Удалить`

- временно ничего не делает;
- оставляется как заглушка без функционала.

## 7. Состояния пары

Для каждой пары должно храниться отдельное состояние.

Список состояний:
- `Stopped`
- `Running`
- `PauseOnlyClose`
- `StoppingNow`

Кнопки окна являются только отображением этого состояния.
Настоящее состояние хранится в данных сценария.

## 8. Где хранить состояние

Состояние пары хранить в данных `BondScenario`, рядом с настройками сценария, с сохранением в файл `Engine`.

Требование:
- состояние должно сохраняться между перезапусками терминала;
- при открытии окна кнопки и режим работы должны восстанавливаться из сохранённого состояния.

## 9. Восстановление после перезапуска `OsEngine`

При запуске терминала:
1. загрузить сохранённое состояние пары;
2. проверить фактическое наличие открытых позиций по её ногам;
3. привести пару к безопасному состоянию.

Правила восстановления:

- было `Stopped` -> остаётся `Stopped`
- было `Running`, позиции нет -> остаётся `Running`
- было `Running`, позиция есть -> остаётся `Running`
- было `PauseOnlyClose`, позиции нет -> становится `Stopped`
- было `PauseOnlyClose`, позиция есть -> остаётся `PauseOnlyClose`
- было `StoppingNow`, позиции нет -> становится `Stopped`
- было `StoppingNow`, позиция есть -> становится `PauseOnlyClose`

Важно:
- после перезапуска не продолжать аварийный `StopNow` автоматически;
- если до перезапуска шло аварийное закрытие, после старта безопасно переводить пару в `PauseOnlyClose`.

## 10. Логика торговли пары

Каждая пара торгуется независимо от других.

Если в одном боте 10 пар:
- каждая пара отдельно проверяет свой спред;
- каждая пара отдельно имеет своё состояние;
- можно запустить одну, поставить на паузу другую, остановить третью.

Одна пара не должна менять состояние другой.

## 11. Общий `Regime` бота

Общий `Regime` у `ttSpreadBot` в v1 убирается из пользовательских параметров.

Причина:
- каждая пара должна управляться отдельно через своё окно;
- общий рубильник добавляет лишнюю сложность;
- глобальное управление всеми парами можно добавить позже отдельной доработкой.

Последствие:
- бот всегда обрабатывает пары по их локальному состоянию;
- если пара `Stopped`, входов по ней нет;
- если пара `Running`, входы разрешены;
- если пара `PauseOnlyClose`, новые входы запрещены, открытая позиция сопровождается до выхода;
- если пара `StoppingNow`, новые входы запрещены, идёт аварийное закрытие.

Старые строки `Regime` в файле параметров бота после удаления параметра не используются.

Глобальный аварийный рубильник для всех пар не входит в v1.

## 12. Логика входа и выхода

Для режима `Продать базу, купить фьючерс`:
- вход при `currentSpread <= MinSpread`
- выход при `currentSpread >= MaxSpread`

Для режима `Купить базу, продать фьючерс`:
- вход при `currentSpread >= MaxSpread`
- выход при `currentSpread <= MinSpread`

## 13. Проверка спреда

- оставить текущую модель проверки примерно раз в `1 секунду`;
- не переводить в тиковую механику на этом этапе;
- логика срабатывает на последнем доступном значении текущего спреда.

## 14. Валидация настроек

Обязательная проверка:
- `MaxSpread > MinSpread`

Если условие нарушено:
- пара не должна запускаться;
- должна быть явная ошибка в лог;
- желательно визуально подсветить неверные поля.

Также ошибки должны мешать `Старту`, если:
- ноги не подключены;
- нет данных по инструментам;
- сценарий не готов к торговле;
- `ArbitrationIceberg` не готов.

## 15. Поля коинтеграции

Поля:
- `Отклонение коинтеграции`
- `Длина коинтеграции`

в этой версии переиспользуются под счётчик циклов конкретной пары.

Требование:
- поле `Отклонение коинтеграции` переименовать в `Циклов нужно`;
- поле `Длина коинтеграции` переименовать в `Циклов сделано`;
- оба значения хранить на уровне `BondScenario`, а не в общих параметрах `ttSpreadBot`;
- `Циклов нужно = 0` означает без ограничения по числу циклов;
- `Циклов сделано` увеличивается после полного цикла `вход -> выход`;
- если `Циклов нужно > 0` и `Циклов сделано >= Циклов нужно`, пара переходит в `Stopped` и новые входы не открывает.

Логика коинтеграции в v1 не используется.

## 16. Настройки исполнения ордеров

Поля из вкладок `Вход в позицию` и `Выход из позиции` продолжают работать как сейчас:
- `Объем общий`
- `Один ордер`
- `Тип ордера`
- `Положение`
- `Проскальзывание`
- `Время жизни`
- `Частота ордера`

Их смысл:
- `SpreadBot` решает, когда входить/выходить;
- `ArbitrationIceberg` решает, как именно исполнять вход/выход по настройкам вкладок.

## 17. Что должно быть в логах

Нужно логировать:
- запуск пары;
- переход пары в `PauseOnlyClose`;
- запуск аварийного `StopNow`;
- восстановление состояния пары после перезапуска;
- отказ в старте из-за невалидных параметров;
- отказ в торговле из-за неготовности сценария/ног.
- достижение лимита циклов по конкретной паре.

## 18. Ограничения по реализации

- минимальные изменения ядра;
- не трогать лишние части платформы;
- без рефакторинга ради красоты;
- использовать существующие механизмы `BondScenario` и `ArbitrationIceberg` там, где это возможно.

## 19. Перед началом кодинга

Перед правками обязательно сделать отдельный git-коммит текущего состояния как точку отката.
